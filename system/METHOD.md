# METHOD · 这套知识系统为什么这样设计

本文回答一个问题：**为什么这样组织知识，人更容易学会？** 每个架构决策都对应一条有实证研究支持的学习科学原理。改架构之前先读本文。

## 从证据到架构

| 学习科学证据 | 本库的架构决策 |
| --- | --- |
| **检索练习**：主动回忆对长期记忆的效果远超重读（Roediger & Karpicke 2006；Dunlosky et al. 2013 综述把重读、划线评为"低效用"） | 每课末尾有自测；每里程碑有过关清单；[tools/quiz.py](../tools/quiz.py) 做间隔检索 |
| **间隔重复 + 交错**：把复习分散在时间上、混合不同题型，好过集中轰炸（MIT 教学研究综述） | quiz.py 用 1-3-7-14 天间隔抽题；里程碑过关清单混合前面的能力 |
| **掌握学习（Mastery Learning）**：Bloom 的研究发现"过关才前进 + 按需补课"能逼近一对一辅导效果 | 里程碑 = 关卡：过关清单 + 项目，不达标不前进；prep/ 提供按需补课 |
| **项目驱动 / 做中学**：真实任务是动机与整合的来源（PBL 研究；fast.ai 的自顶向下教学法） | 每个里程碑以项目收尾，M0 结束就有能跑的作品；理论围绕项目被"需要"时才深入 |
| **认知负荷理论**：工作记忆有限，需分块、分段、样例渐退 | 课的粒度 1-2 小时；每课"样例 → 补全 → 独立做"三段式；参考与课分离 |
| **元认知**：能准确评估"我会不会"本身就是学习能力 | 过关清单全部用行为动词（"你能向别人解释 X 吗"），逼出真实的自我评估 |
| **建立于已知之上**：诊断先行，避免迷路或重复（OSSU 的 Intro→Core 分层逻辑） | [START](../START.md) 三问定位起点；轨道分层，同类背景者有最短路径 |

## 对标对象

- **OSSU**（16 万星的自学大学）：分层课程表 + 每层项目验收 + 进度可视。本库的"轨道→里程碑→过关"直接受其启发，但把"外部课程链接"换成了"自研课 + 本地项目"。
- **MDN / Diátaxis**：教程（tutorial）、指南（how-to）、参考（reference）、解释（explanation）四分离。本库对应：课（tracks）、排障与速查（references/）、题库（practice）。
- **fast.ai**：先跑通再讲原理。本库把数学从"开学第一周"移到 prep/，用到才学。

| 练习 | practice.md / practice/ | 题目+提示+答案 | —— |
| 参考 | references/ | 速查、术语、公式、排障 | 教学叙事 |
| 补课 | prep/ | Python / 数学分册 | 与主线绑定 |

## 旧架构 → 新架构（为什么不是缝补）

| 旧（按学科目录组织） | 新（按能力里程碑组织） |
| --- | --- |
| 12 章线性排布，"数学基础"前置 1-2 周 | 里程碑制，M0 第 3 课就跑出第一个程序；数学按需插入 |
| 章与章之间没有闸门 | 过关清单 + 项目验收，防止"看完了但不会" |
| README 是目录页 | README 是教学设计（目标、课表、项目、验收） |
| 练习散落各章末尾 | 练习与里程碑绑定，过关必做 |
| 没有复习机制 | quiz.py 间隔检索，对抗遗忘曲线 |
| 只有内容维度 | 内容 + 进度（ROADMAP 勾选）+ 诊断（START）三维 |
