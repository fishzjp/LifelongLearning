# 写作规范：怎样写出一篇初学者能读懂的教程
本规范适用于本仓库所有教程文档。它回答一个问题：**什么样的文档，初学者愿意读完、能学会、还会推荐给别人？**

写之前先想清楚三件事：

1. **读者是谁**——默认读者是"聪明的初学者"：会装软件、会照着敲命令，但不具备该领域的背景知识。不要假设读者"应该知道"任何术语。
2. **读完能做什么**——每篇文档开头用一两句话告诉读者：读完这篇，你能动手做出什么、能解释清楚什么。
3. **读者卡在哪里**——初学者放弃一篇教程，通常不是内容太难，而是：术语没解释、步骤跳了、代码跑不起来、看不出学了有什么用。写作的全部功夫，都在消除这四个断点。

## 一、教学设计：先想"怎么教"，再动笔
参考公认优秀教程（MDN、Microsoft Learn、微软《AI Agents for Beginners》、Datawhale 系列）的共性做法：

### 1. 故事先行，定义后置
先给读者一个具体场景，再给抽象定义。反例是开头就甩一串术语定义。

```
✗ 卷积是一种数学运算，定义为 (f*g)(t) = ∫ f(τ)g(t-τ)dτ ...

✓ 想象你拿着一个 3×3 的小放大镜，在照片上一格一格滑动，
  每次只看镜框里的 9 个像素，算出一个新数值。
  这个"滑动 + 计算"的动作，就叫卷积。
  （数学定义见第 3 节）
```

### 2. 每个抽象概念配一个人话比喻
比喻不必严格精确，但要标注适用边界。格式：比喻 + 一句"哪里不像"。

> 上下文窗口像一块白板：模型每轮推理时把所有信息抄上去看。哪里不像？白板可以回头翻，上下文窗口每轮都是重新誊写，旧的会被截断。

### 3. 用反例教学
只讲"怎么做对"，读者记不住。要展示"做错会怎样"。错误示范 + 后果 + 正确做法，比单纯正确做法有效三倍。

### 4. 能力阶梯
概念辨析用"最小代码差"：两段只差一行的代码，让读者看清那行代码的作用。不要一上来给 100 行完整工程。

### 5. 动手优先
每篇文档至少有一个"跟着敲"的环节，10 分钟内能看到输出。理论讲解超过两屏，就该插入一个验证性的小实验。

### 6. 章末自测
用行为动词出题：不要"理解了吗？"，要"你能向同事解释 X 和 Y 的区别吗？""把这段代码的参数改成 N，预测输出会变成什么，再运行验证。"

## 二、文档结构模板
```markdown
# 章节标题（说清楚这一篇讲什么）
一句话总结：读完这篇，你能 ___。

前置知识：___（没有就写"无"）

## 为什么需要 X（解决的痛点，配一个具体场景）
## 核心概念（故事/比喻先行，定义后置）
## 动手实践（可运行的代码，含预期输出）
## 常见错误与排障（初学者真实会踩的坑）
## 小结（3-5 句话，呼应开头的承诺）
## 自测清单（行为动词）
## 延伸阅读（一手来源优先：官方文档、论文）
```

不要求每篇都有全部小节，但"为什么需要"和"动手实践"不能缺。

## 三、去 AI 味清单
以下模式在初学者眼里一眼假，全部禁止：

| 禁止 | 原因 | 替代做法 |
| --- | --- | --- |
| 自评分数（"文档质量 9.7/10"） | 编造数据，损害信任 | 删掉，让内容自己说话 |
| 无来源的百分比（"学习效率提升 75%"） | 同上 | 删掉，或注明数据来源 |
| 徽章堆砌（shields.io 一排） | 装饰性噪音 | 只保留确有信息量的（如 license） |
| 标题 emoji（"## 🎯 学习目标"） | 视觉噪音，干扰扫描 | 标题只用文字 |
| 复读式总结（"XX 的详细讲解与实战指南"） | 零信息量 | 写真正的一句话总结 |
| 空洞三段式（对项目/对团队/对个人） | 填字游戏 | 只写具体、可验证的价值 |
| 占位联系方式（your.email@example.com） | 假信息 | 删掉或写真实信息 |
| AI 过程报告（"Phase 10 完成总结"） | 读者不关心生产过程 | 移入 .backup/，不进主分支 |

emoji 不是完全不能用：正文表格里的 ✅/❌ 表示对错、清单里的复选框，这些有语义的用法可以保留。判断标准：**删掉这个符号，信息量是否受损**。不受损就删。

## 四、代码示例规范
1. **语言标记必须正确**。Python 代码标 `python`，不是 `bash`。终端命令标 `bash`。
2. **可运行**。贴出的代码，读者复制后应该能跑。依赖在代码块前用注释声明：

   ```python
   # 依赖：numpy（安装：pip install numpy）
   import numpy as np
   ```

3. **有函数级注释**。每个函数有 docstring，说明参数、返回值、干什么用。关键行有行内注释。
4. **有预期输出**。用注释给出运行结果，读者才能自查。

   ```python
   print(sum([1, 2, 3]))
   # 输出：6
   ```

5. **由短到长**。先 5 行的最小示例，再给完整工程。不要只用完整工程。
6. **伪代码明确标注**。跑不了的示意代码，开头写明"以下为示意"。

## 五、链接与结构规范
1. **提交前检查链接**。引用本仓库路径前，确认文件存在。目录改名后，全局搜索旧名。
2. **相对路径用仓库根**或文档所在目录，保持一致。
3. **外部链接优先一手来源**：官方文档 > 论文原文 > 高质量二手解读。注明链接指向什么。
4. **目录命名**：模块内统一一种风格（当前为 `序号-英文名`），不要中英混杂。
5. **文件编号不重复**。同一目录下 `01-xxx.md` 只有一个。

## 六、语言规范
1. 中文为主，术语首次出现时附英文原词：**梯度下降（Gradient Descent）**。之后可以只用中文或只用英文，全篇统一。
2. 缩写首次出现时展开：CNN（Convolutional Neural Network，卷积神经网络）。
3. 短句。一个句子超过 40 字，考虑拆开。
4. 直接说"你"，不用"我们"空转（"我们不难发现"→"你会发现"）。
5. 语气平等：不居高临下（"很简单"），也不故作谦卑（"拙见"）。
6. 数字、单位、版本号前后一致。
