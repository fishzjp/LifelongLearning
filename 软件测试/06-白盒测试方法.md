## 什么是白盒测试

### 定义

白盒测试（White Box Testing），也称为结构测试、逻辑驱动测试或基于代码的测试，是一种测试方法，测试人员需要了解程序内部的代码结构、逻辑和实现细节，基于代码的内部逻辑设计测试用例。

**核心思想**：
> 把程序看作一个透明的盒子，关注程序内部的逻辑结构，测试代码的执行路径。

### 白盒测试的特点

#### 优点

1. **覆盖率高**：可以精确测量代码覆盖率
2. **发现深层缺陷**：可以发现逻辑错误、算法错误等
3. **优化代码**：可以发现冗余代码、死代码
4. **早期发现缺陷**：在单元测试阶段就可以发现缺陷

#### 缺点

1. **需要编程知识**：测试人员需要了解代码实现
2. **测试成本高**：需要编写测试代码，维护成本高
3. **可能过度测试**：可能测试一些不必要的代码路径
4. **无法发现需求错误**：只能测试代码是否正确，不能测试需求是否正确

### 白盒测试的适用场景

- **单元测试**：测试单个函数或方法
- **集成测试**：测试模块之间的接口
- **代码审查**：审查代码质量和规范性
- **性能测试**：分析代码性能瓶颈
- **安全测试**：发现安全漏洞

### 白盒测试与黑盒测试的区别

| 对比项 | 白盒测试 | 黑盒测试 |
|--------|----------|----------|
| 测试对象 | 程序代码 | 程序功能 |
| 测试依据 | 代码结构 | 需求规格说明 |
| 测试人员 | 需要编程知识 | 不需要编程知识 |
| 测试覆盖 | 代码覆盖 | 功能覆盖 |
| 测试阶段 | 单元测试 | 集成测试、系统测试 |
| 发现缺陷 | 逻辑错误、算法错误 | 功能错误、接口错误 |

## 代码覆盖基础

### 什么是代码覆盖率

代码覆盖率（Code Coverage）是衡量测试用例对代码覆盖程度的指标，表示被测试执行的代码占总代码的百分比。

**计算公式**：
```
代码覆盖率 = (被执行的代码行数 / 总代码行数) × 100%
```

### 代码覆盖率的重要性

1. **量化测试质量**：客观衡量测试的完整性
2. **发现未测试代码**：找出未被测试的代码路径
3. **指导测试设计**：帮助设计更全面的测试用例
4. **质量保证**：确保关键代码被充分测试

### 代码覆盖率的类型

1. **语句覆盖（Statement Coverage）**：执行了多少条语句
2. **分支覆盖（Branch Coverage）**：执行了多少个分支
3. **条件覆盖（Condition Coverage）**：执行了多少个条件
4. **路径覆盖（Path Coverage）**：执行了多少条路径
5. **函数覆盖（Function Coverage）**：调用了多少个函数

### 覆盖率目标

不同项目对覆盖率的要求不同：

| 项目类型 | 覆盖率目标 | 说明 |
|---------|-----------|------|
| 关键系统 | 90%+ | 金融、医疗等关键系统 |
| 一般系统 | 70-80% | 大多数商业系统 |
| 简单系统 | 50-70% | 简单的工具或脚本 |
| 原型系统 | 30-50% | 快速原型开发 |

**注意**：覆盖率不是越高越好，100%的覆盖率不代表没有缺陷，关键是要覆盖重要的代码路径。

## 语句覆盖

### 定义

语句覆盖（Statement Coverage），也称为行覆盖（Line Coverage），要求测试用例能够执行程序中的每一条语句至少一次。

**覆盖率计算**：
```
语句覆盖率 = (被执行的语句数 / 总语句数) × 100%
```

### 语句覆盖的特点

#### 优点

1. **简单直观**：容易理解和实现
2. **基础覆盖**：是最基本的覆盖要求
3. **工具支持**：大多数工具都支持语句覆盖

#### 缺点

1. **覆盖不足**：即使100%语句覆盖，也可能遗漏某些分支
2. **忽略逻辑**：不关注条件判断的逻辑
3. **可能遗漏错误**：某些逻辑错误可能无法发现

### 实践示例

#### 示例1：简单条件判断

**代码**（Python）：
```python
def calculate_discount(amount, is_vip):
    discount = 0
    if amount >= 1000:
        discount = 0.1
    if is_vip:
        discount = 0.2
    return amount * (1 - discount)
```

**流程图**：
```
开始
  ↓
discount = 0
  ↓
amount >= 1000? ──是──→ discount = 0.1
  ↓否                    ↓
is_vip? ──是──→ discount = 0.2
  ↓否                    ↓
返回 amount * (1 - discount)
  ↓
结束
```

**语句覆盖分析**：

| 语句 | 说明 |
|------|------|
| S1 | discount = 0 |
| S2 | if amount >= 1000: |
| S3 | discount = 0.1 |
| S4 | if is_vip: |
| S5 | discount = 0.2 |
| S6 | return amount * (1 - discount) |

**测试用例设计**：

| 用例ID | amount | is_vip | 执行的语句 | 覆盖率 |
|--------|--------|--------|-----------|--------|
| TC_SC_001 | 1500 | True | S1, S2, S3, S4, S5, S6 | 6/6 = 100% |
| TC_SC_002 | 500 | False | S1, S2, S4, S6 | 4/6 = 67% |

**说明**：
- 用例1可以覆盖所有语句，达到100%语句覆盖
- 用例2只能覆盖部分语句，但两个用例组合可以达到100%语句覆盖

#### 示例2：循环语句

**代码**（Java）：
```java
public int sumArray(int[] arr) {
    int sum = 0;
    for (int i = 0; i < arr.length; i++) {
        sum += arr[i];
    }
    return sum;
}
```

**语句覆盖分析**：

| 语句 | 说明 |
|------|------|
| S1 | int sum = 0; |
| S2 | for (int i = 0; i < arr.length; i++) |
| S3 | sum += arr[i]; |
| S4 | return sum; |

**测试用例设计**：

| 用例ID | 输入数组 | 执行的语句 | 覆盖率 |
|--------|----------|-----------|--------|
| TC_SC_003 | [1, 2, 3] | S1, S2, S3(3次), S4 | 100% |
| TC_SC_004 | [] | S1, S2, S4 | 75% (S3未执行) |

**说明**：
- 用例3可以覆盖所有语句，包括循环体
- 用例4测试空数组，但无法执行循环体，需要两个用例组合

### 语句覆盖的局限性

**示例**：逻辑错误

**代码**：
```python
def check_age(age):
    if age >= 18 and age <= 65:  # 应该是 age >= 18 and age <= 65
        return True
    else:
        return False
```

**问题**：如果代码错误地写成了 `age >= 18 or age <= 65`，语句覆盖无法发现这个错误，因为所有语句都被执行了。

**测试用例**：

| 用例ID | age | 预期结果 | 实际结果（错误代码） |
|--------|-----|----------|---------------------|
| TC_SC_005 | 25 | True | True ✓ |
| TC_SC_006 | 10 | False | True ✗ (错误但语句覆盖100%) |

**结论**：语句覆盖是最低要求，但不足以发现所有缺陷。

## 分支覆盖

### 定义

分支覆盖（Branch Coverage），也称为判定覆盖（Decision Coverage），要求测试用例能够执行程序中的每个分支（真分支和假分支）至少一次。

**覆盖率计算**：
```
分支覆盖率 = (被执行的分支数 / 总分支数) × 100%
```

### 分支覆盖的特点

#### 优点

1. **覆盖更全面**：比语句覆盖更严格
2. **发现逻辑错误**：可以发现条件判断的错误
3. **工具支持**：大多数工具都支持分支覆盖

#### 缺点

1. **不关注条件细节**：不关注复合条件中每个条件的取值
2. **可能遗漏**：某些条件组合可能未被测试

### 实践示例

#### 示例1：简单分支

**代码**（Python）：
```python
def calculate_grade(score):
    if score >= 90:
        return "A"
    elif score >= 80:
        return "B"
    elif score >= 60:
        return "C"
    else:
        return "D"
```

**分支分析**：

| 分支 | 条件 | 真分支 | 假分支 |
|------|------|--------|--------|
| B1 | score >= 90 | return "A" | 继续判断 |
| B2 | score >= 80 | return "B" | 继续判断 |
| B3 | score >= 60 | return "C" | return "D" |

**测试用例设计**：

| 用例ID | score | 执行的分支 | 覆盖率 |
|--------|-------|-----------|--------|
| TC_BC_001 | 95 | B1真 | 1/6 = 17% |
| TC_BC_002 | 85 | B1假, B2真 | 3/6 = 50% |
| TC_BC_003 | 70 | B1假, B2假, B3真 | 5/6 = 83% |
| TC_BC_004 | 50 | B1假, B2假, B3假 | 6/6 = 100% |

**说明**：需要4个测试用例才能达到100%分支覆盖。

#### 示例2：复合条件

**代码**（Java）：
```java
public boolean checkUser(String username, String password) {
    if (username != null && password != null) {
        if (username.length() >= 6 && password.length() >= 8) {
            return true;
        }
    }
    return false;
}
```

**分支分析**：

| 分支 | 条件 | 真分支 | 假分支 |
|------|------|--------|--------|
| B1 | username != null && password != null | 进入内层if | return false |
| B2 | username.length() >= 6 && password.length() >= 8 | return true | return false |

**测试用例设计**：

| 用例ID | username | password | 执行的分支 | 覆盖率 |
|--------|----------|----------|-----------|--------|
| TC_BC_005 | "testuser" | "password123" | B1真, B2真 | 2/4 = 50% |
| TC_BC_006 | "testuser" | "pass" | B1真, B2假 | 4/4 = 100% |
| TC_BC_007 | null | "password123" | B1假 | 3/4 = 75% |
| TC_BC_008 | "testuser" | null | B1假 | 4/4 = 100% |

**说明**：需要4个测试用例才能达到100%分支覆盖。

### 分支覆盖与语句覆盖的关系

- **分支覆盖包含语句覆盖**：如果达到100%分支覆盖，一定达到100%语句覆盖
- **语句覆盖不包含分支覆盖**：100%语句覆盖不一定达到100%分支覆盖

**示例**：

**代码**：
```python
def example(x):
    if x > 0:
        print("positive")
    print("done")
```

**测试用例**：

| 用例ID | x | 语句覆盖 | 分支覆盖 |
|--------|---|----------|----------|
| TC_001 | 1 | 100% | 50% (只覆盖真分支) |
| TC_002 | -1 | 100% | 50% (只覆盖假分支) |
| TC_003 | 1, -1 | 100% | 100% |

## 条件覆盖

### 定义

条件覆盖（Condition Coverage）要求测试用例能够使每个条件的所有可能取值（真/假）都至少执行一次。

**覆盖率计算**：
```
条件覆盖率 = (被执行的条件取值数 / 总条件取值数) × 100%
```

### 条件覆盖的特点

#### 优点

1. **更细致**：关注每个条件的取值
2. **发现条件错误**：可以发现条件判断中的错误

#### 缺点

1. **不关注组合**：不关注条件的组合结果
2. **可能遗漏分支**：即使100%条件覆盖，也可能遗漏某些分支

### 实践示例

#### 示例1：简单条件

**代码**（Python）：
```python
def check_conditions(a, b):
    if a > 0 and b > 0:
        return "both positive"
    elif a > 0 or b > 0:
        return "one positive"
    else:
        return "both negative"
```

**条件分析**：

| 条件 | 真值 | 假值 |
|------|------|------|
| C1 | a > 0 | a <= 0 |
| C2 | b > 0 | b <= 0 |

**条件覆盖测试用例**：

| 用例ID | a | b | C1 | C2 | 覆盖的条件取值 |
|--------|---|---|----|----|---------------|
| TC_CC_001 | 1 | 1 | 真 | 真 | C1真, C2真 |
| TC_CC_002 | -1 | -1 | 假 | 假 | C1假, C2假 |
| TC_CC_003 | 1 | -1 | 真 | 假 | C1真, C2假 |
| TC_CC_004 | -1 | 1 | 假 | 真 | C1假, C2真 |

**说明**：4个测试用例可以达到100%条件覆盖（每个条件的真值和假值都被测试）。

#### 示例2：复合条件

**代码**（Java）：
```java
public boolean validate(String username, String password, boolean isActive) {
    if (username != null && password != null && isActive) {
        return true;
    }
    return false;
}
```

**条件分析**：

| 条件 | 真值 | 假值 |
|------|------|------|
| C1 | username != null | username == null |
| C2 | password != null | password == null |
| C3 | isActive == true | isActive == false |

**条件覆盖测试用例**：

| 用例ID | username | password | isActive | C1 | C2 | C3 |
|--------|----------|----------|----------|----|----|----|
| TC_CC_005 | "user" | "pass" | true | 真 | 真 | 真 |
| TC_CC_006 | null | "pass" | true | 假 | 真 | 真 |
| TC_CC_007 | "user" | null | true | 真 | 假 | 真 |
| TC_CC_008 | "user" | "pass" | false | 真 | 真 | 假 |

**说明**：4个测试用例可以达到100%条件覆盖。

### 条件覆盖与分支覆盖的关系

- **条件覆盖不包含分支覆盖**：100%条件覆盖不一定达到100%分支覆盖
- **分支覆盖不包含条件覆盖**：100%分支覆盖不一定达到100%条件覆盖

**示例**：

**代码**：
```python
def example(a, b):
    if a > 0 and b > 0:
        return 1
    return 0
```

**测试用例**：

| 用例ID | a | b | 条件覆盖 | 分支覆盖 |
|--------|---|---|----------|----------|
| TC_001 | 1 | 1 | 50% (C1真, C2真) | 50% (只覆盖真分支) |
| TC_002 | -1 | -1 | 50% (C1假, C2假) | 50% (只覆盖假分支) |
| TC_003 | 1, -1 | -1, 1 | 100% | 100% |

**说明**：需要同时考虑条件覆盖和分支覆盖。

## 判定/条件覆盖

### 定义

判定/条件覆盖（Decision/Condition Coverage）要求测试用例既满足分支覆盖，又满足条件覆盖，即每个分支的真假值都要执行，每个条件的真假值都要执行。

**覆盖率计算**：
```
判定/条件覆盖率 = (被执行的分支数 + 被执行的条件取值数) / (总分支数 + 总条件取值数) × 100%
```

### 判定/条件覆盖的特点

#### 优点

1. **覆盖更全面**：结合了分支覆盖和条件覆盖的优点
2. **发现更多缺陷**：可以发现分支和条件相关的错误

#### 缺点

1. **测试用例多**：需要更多的测试用例
2. **可能冗余**：某些测试用例可能是冗余的

### 实践示例

**代码**（Python）：
```python
def check_user(username, password, is_vip):
    if username != None and password != None and is_vip:
        return "VIP user"
    elif username != None and password != None:
        return "Normal user"
    else:
        return "Invalid"
```

**条件分析**：

| 条件 | 真值 | 假值 |
|------|------|------|
| C1 | username != None | username == None |
| C2 | password != None | password == None |
| C3 | is_vip == True | is_vip == False |

**分支分析**：

| 分支 | 条件 | 真分支 | 假分支 |
|------|------|--------|--------|
| B1 | C1 and C2 and C3 | return "VIP user" | 继续判断 |
| B2 | C1 and C2 | return "Normal user" | return "Invalid" |

**判定/条件覆盖测试用例**：

| 用例ID | username | password | is_vip | 覆盖的条件 | 覆盖的分支 |
|--------|----------|----------|--------|-----------|-----------|
| TC_DC_001 | "user" | "pass" | True | C1真, C2真, C3真 | B1真 |
| TC_DC_002 | "user" | "pass" | False | C1真, C2真, C3假 | B1假, B2真 |
| TC_DC_003 | "user" | None | True | C1真, C2假, C3真 | B1假, B2假 |
| TC_DC_004 | None | "pass" | True | C1假, C2真, C3真 | B1假, B2假 |
| TC_DC_005 | None | None | False | C1假, C2假, C3假 | B1假, B2假 |

**说明**：5个测试用例可以达到100%判定/条件覆盖。

## 路径覆盖

### 定义

路径覆盖（Path Coverage）要求测试用例能够执行程序中所有可能的执行路径。

**覆盖率计算**：
```
路径覆盖率 = (被执行的路径数 / 总路径数) × 100%
```

### 路径覆盖的特点

#### 优点

1. **覆盖最全面**：是最强的覆盖标准
2. **发现所有路径错误**：可以发现所有路径相关的错误

#### 缺点

1. **路径数量庞大**：循环和条件组合会导致路径数量呈指数增长
2. **不可行**：对于复杂程序，完全路径覆盖通常不可行
3. **测试成本高**：需要大量的测试用例

### 基本路径测试

由于完全路径覆盖不可行，实际中通常使用**基本路径测试**（Basis Path Testing）：

1. **识别基本路径**：找出线性无关的路径
2. **设计测试用例**：为每条基本路径设计测试用例
3. **执行测试**：执行所有基本路径

### 实践示例

#### 示例1：简单路径

**代码**（Python）：
```python
def example(x, y):
    if x > 0:
        if y > 0:
            return 1
        else:
            return 2
    else:
        return 3
```

**路径分析**：

| 路径 | 条件 | 执行语句 |
|------|------|----------|
| P1 | x > 0, y > 0 | if x > 0, if y > 0, return 1 |
| P2 | x > 0, y <= 0 | if x > 0, if y > 0(假), return 2 |
| P3 | x <= 0 | if x > 0(假), return 3 |

**路径覆盖测试用例**：

| 用例ID | x | y | 覆盖的路径 | 预期结果 |
|--------|---|---|-----------|----------|
| TC_PC_001 | 1 | 1 | P1 | 1 |
| TC_PC_002 | 1 | -1 | P2 | 2 |
| TC_PC_003 | -1 | 1 | P3 | 3 |

**说明**：3个测试用例可以达到100%路径覆盖。

#### 示例2：循环路径

**代码**（Java）：
```java
public int findMax(int[] arr) {
    if (arr == null || arr.length == 0) {
        return -1;
    }
    int max = arr[0];
    for (int i = 1; i < arr.length; i++) {
        if (arr[i] > max) {
            max = arr[i];
        }
    }
    return max;
}
```

**路径分析**：

| 路径 | 条件 | 说明 |
|------|------|------|
| P1 | arr == null | 返回-1 |
| P2 | arr.length == 0 | 返回-1 |
| P3 | arr.length == 1 | 循环0次，返回arr[0] |
| P4 | arr.length > 1, 循环中更新max | 正常路径 |
| P5 | arr.length > 1, 循环中不更新max | 所有元素相同 |

**路径覆盖测试用例**：

| 用例ID | 输入数组 | 覆盖的路径 | 预期结果 |
|--------|----------|-----------|----------|
| TC_PC_004 | null | P1 | -1 |
| TC_PC_005 | [] | P2 | -1 |
| TC_PC_006 | [5] | P3 | 5 |
| TC_PC_007 | [1, 3, 2] | P4 | 3 |
| TC_PC_008 | [2, 2, 2] | P5 | 2 |

**说明**：5个测试用例可以覆盖主要路径。

### 路径覆盖的局限性

1. **循环路径**：循环次数不同会产生不同的路径，无法完全覆盖
2. **路径爆炸**：条件组合会导致路径数量呈指数增长
3. **不可行路径**：某些路径在逻辑上不可能执行

**解决方案**：
- 使用基本路径测试
- 限制循环次数（如0次、1次、多次）
- 关注关键路径

## MC/DC覆盖

### 定义

MC/DC覆盖（Modified Condition/Decision Coverage，修改条件/判定覆盖）是一种更强的覆盖标准，要求：

1. **每个条件**的所有可能取值都要执行
2. **每个判定**的所有可能结果都要执行
3. **每个条件**都要独立影响判定的结果

### MC/DC覆盖的特点

#### 优点

1. **覆盖强度高**：比判定/条件覆盖更强
2. **发现独立错误**：可以发现条件独立影响判定的错误
3. **测试用例相对较少**：比完全路径覆盖的测试用例少

#### 缺点

1. **设计复杂**：需要仔细分析条件的独立性
2. **工具支持有限**：不是所有工具都支持MC/DC覆盖

### 实践示例

**代码**（Python）：
```python
def check_conditions(a, b, c):
    if (a > 0 and b > 0) or c > 0:
        return True
    return False
```

**条件分析**：

| 条件 | 说明 |
|------|------|
| C1 | a > 0 |
| C2 | b > 0 |
| C3 | c > 0 |

**判定**：D = (C1 and C2) or C3

**MC/DC覆盖测试用例**：

| 用例ID | a | b | c | C1 | C2 | C3 | D | 独立影响 |
|--------|---|---|---|----|----|----|----|---|----------|
| TC_MCDC_001 | 1 | 1 | -1 | 真 | 真 | 假 | 真 | C1和C2独立影响D |
| TC_MCDC_002 | -1 | 1 | -1 | 假 | 真 | 假 | 假 | C1独立影响D |
| TC_MCDC_003 | 1 | -1 | -1 | 真 | 假 | 假 | 假 | C2独立影响D |
| TC_MCDC_004 | -1 | -1 | 1 | 假 | 假 | 真 | 真 | C3独立影响D |
| TC_MCDC_005 | -1 | -1 | -1 | 假 | 假 | 假 | 假 | 所有条件为假 |

**说明**：5个测试用例可以达到MC/DC覆盖，每个条件都独立影响了判定的结果。

## 代码审查

### 定义

代码审查（Code Review）是一种通过检查代码来发现缺陷、提高代码质量的方法。

### 代码审查的目的

1. **发现缺陷**：在代码合并前发现缺陷
2. **提高质量**：提高代码质量和可维护性
3. **知识分享**：团队成员之间分享知识
4. **统一规范**：确保代码符合编码规范

### 代码审查的类型

#### 1. 正式审查（Formal Review）

- 有明确的流程和角色
- 需要准备审查材料
- 记录审查结果

#### 2. 非正式审查（Informal Review）

- 开发者之间互相审查
- 流程灵活
- 快速反馈

#### 3. 走查（Walkthrough）

- 作者讲解代码
- 审查者提问
- 发现问题和改进建议

#### 4. 检查（Inspection）

- 最正式的审查方式
- 有明确的角色和流程
- 记录所有发现的问题

### 代码审查清单

#### 功能正确性

- [ ] 代码是否实现了需求？
- [ ] 边界条件是否处理？
- [ ] 异常情况是否处理？
- [ ] 返回值是否正确？

#### 代码质量

- [ ] 代码是否清晰易读？
- [ ] 变量命名是否规范？
- [ ] 函数是否单一职责？
- [ ] 是否有重复代码？

#### 性能

- [ ] 是否有性能问题？
- [ ] 算法复杂度是否合理？
- [ ] 是否有不必要的循环？
- [ ] 资源是否及时释放？

#### 安全性

- [ ] 是否有SQL注入风险？
- [ ] 是否有XSS风险？
- [ ] 输入是否验证？
- [ ] 权限是否检查？

#### 可维护性

- [ ] 是否有注释？
- [ ] 注释是否准确？
- [ ] 代码结构是否合理？
- [ ] 是否易于扩展？

### 代码审查流程

1. **准备阶段**
   - 作者准备代码和说明
   - 选择审查者
   - 安排审查时间

2. **审查阶段**
   - 审查者阅读代码
   - 记录发现的问题
   - 提出改进建议

3. **讨论阶段**
   - 作者和审查者讨论问题
   - 确定需要修改的内容
   - 记录讨论结果

4. **修改阶段**
   - 作者修改代码
   - 解决所有问题

5. **验证阶段**
   - 审查者验证修改
   - 确认问题已解决

### 代码审查工具

#### 1. GitHub Pull Request

**特点**：
- 集成在GitHub中
- 支持行内评论
- 支持代码讨论

#### 2. Gerrit

**特点**：
- 代码审查平台
- 支持代码评分
- 与Git集成

#### 3. Code Review工具

- **Phabricator**：Facebook开发的代码审查工具
- **Review Board**：开源的代码审查工具
- **Crucible**：Atlassian的代码审查工具

静态分析（Static Analysis）是在不执行代码的情况下，通过分析代码的结构、语法、语义来发现潜在问题的方法。

### 静态分析的目的

1. **发现缺陷**：发现代码中的潜在缺陷
2. **代码质量**：评估代码质量
3. **规范检查**：检查代码是否符合规范
4. **安全漏洞**：发现安全漏洞

   - 免费开源

3. **PMD**
   - 代码规范检查
   - 发现代码异味

4. **Checkstyle**
   - 代码风格检查
   - 可配置规则

   - 集成多个工具

## 白盒测试实践

### 单元测试框架

#### Java单元测试框架

```java
import org.junit.Test;
```

2. **TestNG**
   - 功能更强大
   - 支持测试组
   - 支持并行测试

#### Python单元测试框架

1. **unittest**
   - Python标准库
   - 类似JUnit

**示例**：
```python
import unittest

class TestCalculator(unittest.TestCase):
```

   - 更简洁

   - 插件丰富

**示例**：
```python
def test_add():
    calc = Calculator()
    assert calc.add(2, 3) == 5
```

### 测试驱动开发（TDD）

#### TDD流程

1. **编写测试**：先编写失败的测试用例
2. **运行测试**：确认测试失败
3. **编写代码**：编写最少的代码使测试通过
4. **重构**：重构代码，保持测试通过
5. **重复**：重复上述步骤

#### TDD的优点

1. **设计更好**：迫使思考接口设计
2. **测试覆盖率高**：每个功能都有测试
3. **信心**：修改代码时有测试保障
4. **文档**：测试即文档

#### TDD的示例

**步骤1：编写测试**
```python
def test_calculate_discount():
    assert calculate_discount(1000, True) == 900
```

**步骤2：运行测试（失败）**
```
AssertionError: function 'calculate_discount' not defined
```

**步骤3：编写代码**
```python
def calculate_discount(amount, is_vip):
    if is_vip:
        return amount * 0.9
    return amount
```

**步骤4：运行测试（通过）**
```
test passed
```

**步骤5：重构（如果需要）**

### 白盒测试最佳实践

1. **覆盖关键路径**：重点测试关键业务逻辑
2. **测试边界值**：测试边界条件和异常情况
3. **测试错误处理**：测试异常处理和错误恢复
4. **保持测试独立**：每个测试用例应该独立
5. **测试命名清晰**：测试方法名应该清晰表达测试意图
6. **及时更新测试**：代码变更时及时更新测试
7. **代码审查**：定期进行代码审查
8. **使用工具**：使用代码覆盖工具和静态分析工具

## 实践案例

### 案例1：用户认证功能测试

**代码**（Python）：
```python
def authenticate(username, password, max_attempts=3):
    if not username or not password:
        return {"success": False, "message": "用户名和密码不能为空"}
    
    attempts = 0
    while attempts < max_attempts:
        if check_credentials(username, password):
            return {"success": True, "message": "登录成功"}
        attempts += 1
        if attempts >= max_attempts:
            return {"success": False, "message": "登录失败，账号已锁定"}
    return {"success": False, "message": "登录失败"}
```

| 分支覆盖 | TC_003 | "user" | "wrong" | 登录失败 |
| 路径覆盖 | TC_004 | "user" | "pass" | 登录成功（第一次尝试） |
| 路径覆盖 | TC_005 | "user" | "wrong" | 登录失败，账号已锁定（3次失败） |

### 案例2：计算器功能测试

**代码**（Java）：
```java
public class Calculator {
    public int divide(int a, int b) {
        if (b == 0) {
            throw new IllegalArgumentException("除数不能为0");
        }
        return a / b;
    }
```

| divide | TC_002 | a=10, b=0 | 抛出异常 | 分支覆盖 |
| calculateDiscount | TC_003 | amount=100, isVip=true | 80 | 路径覆盖 |
