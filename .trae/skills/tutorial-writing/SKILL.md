# 教程写作（本仓库专用）
你正在为 LifelongLearning 学习笔记库写或改中文教程。本技能是 [docs/写作规范.md](../../../docs/写作规范.md) 的执行版：按下面的规则写，写完按"提交前检查"验证。完整原理与示例见规范原文。

## 动笔前先回答三个问题（写进文档开头）
1. **读者是谁**：默认"聪明的初学者"——会装软件、会照着敲命令，但没有本领域背景。不假设读者"应该知道"任何术语。
2. **读完能做什么**：开头一两句话写明，读完能动手做出什么、能解释清什么。
3. **读者会卡在哪**：术语没解释、步骤跳了、代码跑不起来、看不出学了有什么用。全文的功夫都在消除这四个断点。

## 教学设计六原则
1. **故事先行，定义后置**：先给具体场景，再给抽象定义。反例是开头甩数学定义。
2. **抽象概念配人话比喻**：比喻 + 一句"哪里不像"标注适用边界。
3. **用反例教学**：错误示范 + 后果 + 正确做法。
4. **能力阶梯**：概念辨析用最小代码差（两段只差一行）；先 5 行最小示例再给完整工程，不要只给 100 行工程。
5. **动手优先**：每篇至少一个 10 分钟内能看到输出的"跟着敲"环节；理论超两屏必须插小实验。
6. **章末自测用行为动词**："你能向同事解释 X 和 Y 的区别吗"，禁止"理解了吗？"。

## 文档结构模板
```markdown
# 章节标题
一句话总结：读完这篇，你能 ___。
前置知识：___（没有就写"无"）

## 为什么需要 X
## 核心概念（故事/比喻先行）
## 动手实践（可运行代码 + 预期输出）
## 常见错误与排障
## 小结
## 自测清单
## 延伸阅读（一手来源优先）
```

"为什么需要"和"动手实践"两节不可缺，其余可按内容取舍。

## 禁止清单（AI 味，一律不得出现）
| 禁止 | 替代 |
| --- | --- |
| 自评分数（"文档质量 9.7/10"） | 删掉，让内容说话 |
| 无来源百分比（"学习效率提升 75%"） | 删掉或注明来源 |
| shields.io 徽章行 | 删掉 |
| 标题装饰 emoji（"## 🎯 学习目标"） | 标题只用文字 |
| "待补充"占位符 | 要么写完，要么删掉该栏目 |
| 复读式总结（"XX 的详细讲解与实战指南"） | 写真正的一句话总结 |
| 空洞三段式（对项目/对团队/对个人） | 只写具体可验证的价值 |
| 占位联系方式（your.email@example.com） | 删掉 |
| 虚构章节/文件/代码目录的链接 | 只链接实际存在的文件 |

语义性符号可保留（表格 ✅/❌、清单复选框）。判断标准：删掉该符号信息量是否受损，不受损就删。

## 代码块规则
- 语言标记必须正确：Python 代码标 `python`，终端命令标 `bash`，示意图/伪代码标 `text` 或注明"示意"。
- 依赖在代码块内用注释声明：`# 依赖：numpy（安装：pip install numpy）`。
- 每个函数有注释，说明参数、返回值、用途（用户仓库规则）。
- 关键示例附预期输出：`# 输出：6`。

## 链接与语言规则
- 仓库内链接：写之前确认目标存在；目录改名后全局搜旧名。
- 外部链接一手来源优先：官方文档 > 论文原文 > 二手解读。
- 术语首次出现附英文：**梯度下降（Gradient Descent）**；缩写首次展开。
- 短句为主；对读者说"你"，不用"我们不难发现"。

## 提交前检查（必须全部通过）

1. 运行链接、AI 味残留与代码块围栏配对检查（预期三项全 0；围栏不配对会破坏渲染与后续检查的准确性）：

   ```bash
   python3 ${CLAUDE_SKILL_DIR}/scripts/check_docs.py
   ```

2. grep 验证无占位符：`grep -rn "待补充" <改动文件>` 应无输出。
3. 对照规范第七节自查清单逐项打勾。
4. 删除或移动文件前，先复制到 `.backup/<日期-操作>/`（用户仓库规则，防误删）。
5. 更新 CHANGELOG.md（Keep a Changelog 格式，只写事实不写自评）。
